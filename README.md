# quark-cdn-412-downloader

从夸克网盘分享链接下载超大文件（实测 33.75 GB），绕过阿里 CDN 的 **412 Precondition Failed** 风控拦截。

本项目的方案在 2026-11-14 从一次真实的 33.75 GB 下载中产出并验证通过（RAR CRC 全部校验通过）。

## 这玩意儿解决什么问题

夸克网盘的分享文件直链有两条坑：

1. **直链被按 TLS 指纹拦截**：Python 的 `urllib`/`requests`、Windows BITS 都过不去，返回 412 或连接重置。**必须用系统自带的 `curl.exe`**（Windows 上是 Schannel，TLS 指纹和浏览器/客户端接近）。
2. **412 是概率性的，还随时间波动**：同一个直链连打，有的请求 206 成功，有的 412；而且这个比例会随累计下载量急剧恶化（本次实测从 30% 掉到 0%）。

第 2 条是核心难点。本项目用「分块 + 强校验 + 低频探针等窗口」的架构解决它。

## 快速开始

### 1. 准备 Cookie

需要夸克网页/客户端的登录态。用浏览器的 Cookie（`__pus`、`__kps` 等）导出成 JSON：

```json
[{"host": ".quark.cn", "name": "__pus", "value": "..."},
 {"host": ".quark.cn", "name": "__kps", "value": "..."}]
```

存成 `cookies.json`（**已经在 .gitignore 里，别提交**）。

### 2. 拿分享 ID

分享链接 `https://pan.quark.cn/s/YOUR_PWD_ID` 里的 `YOUR_PWD_ID` 就是 `--pwd-id`。

### 3. 跑

```bash
python quark_downloader.py \
  --pwd-id YOUR_PWD_ID \
  --cookies cookies.json \
  --out "D:/downloads/bigfile.rar" \
  --chunk-mb 64 \
  --workers 8
```

支持断点续传：中断后重跑同一条命令，会自动跳过已完成的分块。

## 核心设计

### 分块

大文件切成 64 MB 的块（`--chunk-mb` 可调）。每块独立发起 Range 请求。

**为什么分块**：大 Range 请求更容易被风控掐；小请求还能钻过去。本次实测 64 MB 全块在风控期 0% 命中，但 4 MB 子段曾拿到 206。

### 强校验（这是最关键的部分）

每个分块必须同时满足以下全部条件，才被认可为完成：

1. HTTP 状态码 == 206
2. 下载字节数 == 期望字节数（精确相等）
3. `Content-Range` 响应头与请求的区间精确匹配
4. **全文扫描不含 `<!DOCTYPE` 或 `412 Precondition`**

第 4 条是血的教训。前一代脚本用 `curl -C -` 断点续传，结果 CDN 返回的 262 字节 412 错误页被当成进度追加进分块文件，导致整个 33.75 GB 数据错位、白下 2 GB。

**永远不要相信"curl 退出码 0"或"文件变大了"就代表下载成功。**

### 412 重试

命中 412 时立即丢弃该次请求的数据，重新发起。单块最多重试 80 次。

412 失败只花约 0.4 秒，成本极低，所以"重试到成功"是划算的——前提是用上面的强校验挡住污染。

### 低频探针等窗口（应对风控收紧）

当 412 命中率降到极低（比如连续 25 次全失败），继续硬刷只会加剧风控。本项目带有补块工作模式：

- 每 45 秒只发 **1 个** 4 MB 探针请求
- 探针一旦返回 206，说明 CDN 窗口恢复，立刻并发补齐所有缺失块
- 补齐后自动合并、校验

本次实测：风控从 0% 恢复到可下载，靠的就是等这个窗口（22:10 归零 → 22:25 恢复）。

## 实测数据（2026-11-14，33.75 GB）

详细报告见 [docs/field-report.md](docs/field-report.md)。

| 时间 | 412 命中率 | 备注 |
|------|-----------|------|
| 21:11 | 30%（20 次中 6 次成） | 大分块也能成 |
| 22:10 | ~0%（1/4/16/64 MB 几乎全 412） | 下满约 30 GB 后急剧收紧 |
| 22:25 | 恢复 | 19 个缺失块 70 秒内补齐 |

- 8 并发聚合带宽：实测 9 MB/s，缓存热了后稳定 15~30 MB/s
- 全程用时：约 38 分钟下完 540 块

## 校验下载结果

```bash
python verify.py --file "D:/downloads/bigfile.rar"
```

会检查：大小、文件魔数、以及（如果安装了 WinRAR）调用 `UnRAR.exe t` 做 CRC 全量校验。

**注意：不要用夸克 API 返回的 `md5` 字段校验整文件。** 本次实测该字段与下载到的整文件 MD5 不符，但文件其实是完好的（RAR CRC 全过）。那个字段不是整文件哈希。

## 环境要求

- Windows（依赖系统 `curl.exe` 的 Schannel TLS，Linux 下可用系统 curl 但未验证）
- Python 3.8+
- 可选：WinRAR（用于 CRC 校验，`C:\Program Files\WinRAR\UnRAR.exe`）
